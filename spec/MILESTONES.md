# MILESTONES – Simon

מסמך זה מגדיר את סדר הפיתוח של משחק Simon בהתאם ל־`PRD.md`, ל־`ARCHITECTURE.md` ול־`DESIGN.md`. הפיתוח כולל שני מסכים בלבד: משחק ואודות. תצוגת סיום המשחק היא **מצב במסך המשחק**, ולא מסך נוסף.

## Milestone 1 – בסיס האפליקציה ומשחק ראשון עובד

**שם ומטרה:** להקים פרויקט Web תקין ולאפשר למשתמש להתחיל משחק Simon, לצפות ברצף ולשחזר אותו במובייל.

**מה יש לממש:**
- הקמת פרויקט React + TypeScript עם Vite, ניהול קוד ב־Git ו־GitHub Repository.
- שלד מסך המשחק ב־RTL ובגישה Mobile-first, בהתאם ל־Wireframes ול־Mockups: כותרת, נתוני שלב וניקוד, לוח ארבעת רבעי העיגול והודעות מצב.
- שימוש ב־CSS ובשפה החזותית של `DESIGN.md`, לרבות צבעי Simon והיררכיית טקסט.
- כפתור ״התחל״; יצירת רצף אקראי של צבע אחד באמצעות Web Crypto API; הצגת הרצף בהארה של כ־600ms לצבע ובהפסקה קצרה.
- ארבעה צלילים מובחנים באמצעות Web Audio API, בהצגת הרצף ובלחיצות השחקן; אתחול AudioContext בעקבות לחיצה יזומה.
- חסימת קלט בזמן הצגת הרצף; הודעות ״צפה ברצף״ ו״תורך!״; קליטת שחזור הרצף ללא הגבלת זמן.
- הפרדה לוגית בין Game Rules, Game Controller, Sequence Scheduler, Audio Adapter ו־UI, ללא Backend או Database.

**תוצר מצופה:** גרסת משחק ראשונית שפועלת בדפדפן נייד: לחיצה על ״התחל״ מציגה צבע וצליל, ולאחר מכן השחקן יכול לחזור על הצבע. התוצר אינו נדרש עדיין להשלים את כל עשרת השלבים.

**Definition of Done:**
- הפרויקט עולה מקומית, ופקודות Build ו־Typecheck מסתיימות ללא שגיאות.
- מסך המשחק מוצג בעברית וב־RTL בפריסת Smartphone, עם ארבעה צבעים במיקומים שהוגדרו.
- ״התחל״ יוצר ומציג רצף באורך אחד; הצבע מואר ונשמע הצליל המתאים.
- בזמן ״צפה ברצף״ לחיצות אינן משפיעות על המשחק; בסיום מוצג ״תורך!״ ומתקבל קלט.
- שחזור הצבע הראשון מזוהה בהצלחה; ארבעת הצבעים והצלילים ניתנים לבדיקה.
- קיימות בדיקות אוטומטיות בסיסיות ליצירת צבע ולזיהוי קלט נכון; הן עוברות.
- הקוד נמצא ב־GitHub Repository.

## Milestone 2 – מחזור משחק מלא, ניקוד וסיום

**שם ומטרה:** להשלים משחק Simon קלאסי מקצה לקצה, כולל עשרה שלבים, תוצאה והתחלה מחדש.

**מה יש לממש:**
- שמירת הרצף הקיים והוספת צבע אקראי אחד בכל שלב, עד עשרה צבעים.
- שחזור מלא לפי הסדר, בדיקת כל לחיצה, התקדמות אוטומטית לאחר ״כל הכבוד!״ והשהיה קצרה.
- ניקוד של נקודה אחת לכל שלב שהושלם; הצגת השלב הנוכחי מתוך 10 והניקוד.
- טעות ראשונה מסיימת את המשחק מיד, עם צליל שגיאה והבהוב קצר.
- תצוגת סיום בתוך מסך המשחק: הודעת הפסד או ״כל הכבוד! ניצחת!״, תוצאה וכפתור ״משחק חדש״.
- שיא ניקוד בזיכרון הדף בלבד: ״משחק חדש״ מאפס ניקוד נוכחי ומשמר שיא; רענון מאפס הכול.
- ניהול תזמונים וביטול פעולות ממתינות כדי למנוע השמעה כפולה, קלט בזמן הצגה או המשך רצף אחרי סיום.
- התאמת מצבי המשחק לעיצוב המוגדר ב־`DESIGN.md`.

**תוצר מצופה:** משחק שלם, עם התקדמות משלב 1 עד 10, הפסד בטעות הראשונה, ניצחון בסיום, ניקוד והתחלה מחדש.

**Definition of Done:**
- בכל שלב אורך הרצף שווה למספר השלב, וכל הרצף הקודם נשמר באותו סדר.
- קלט נכון חלקי אינו מוסיף נקודה; השלמת שלב מוסיפה נקודה אחת ומתחילה אוטומטית את השלב הבא.
- השלמת שלב 10 מציגה ניצחון עם 10 נקודות, ללא שלב 11.
- לחיצה שגויה בכל שלב מסיימת מיד את המשחק עם משוב חזותי וקולי; אין ניסיון נוסף.
- תצוגת הסיום מאפשרת ״משחק חדש״ עם רצף חדש וניקוד נוכחי 0.
- שיא הסשן נשמר בין משחקים באותה טעינת דף, ומתאפס ברענון.
- בדיקות אוטומטיות מכסות התקדמות, ניקוד, שגיאה, ניצחון ואיפוס, ועוברות.

## Milestone 3 – מסך אודות וניווט עם השהיה

**שם ומטרה:** להשלים את שני מסכי המוצר ואת הניווט ביניהם בלי לאבד משחק פעיל.

**מה יש לממש:**
- מסך ״אודות״ לפי `DESIGN.md`: שם המשחק, תיאור קצר, הוראות, ניקוד נוכחי, שיא הסשן וכפתור ״חזרה למשחק״.
- ניווט פנימי ב־React State בלבד בין מסך המשחק למסך אודות, ללא Router וללא מסך שלישי.
- השהיית רצף, צלילים ותזמונים בעת מעבר לאודות; חזרה עקבית לאותו מצב משחק, כולל רצף, התקדמות הקלט והניקוד.
- אפשרות כניסה לאודות גם לפני תחילת משחק וגם לאחר סיומו.
- שמירה על מראה עקבי, טיפוגרפיה בעברית, RTL ופריסה מותאמת לנייד.

**תוצר מצופה:** אפליקציה בעלת שני מסכים מתפקדים, כולל מעבר לאודות וחזרה בטוחה בזמן משחק.

**Definition of Done:**
- ניתן לפתוח את ״אודות״ ולחזור למשחק; כל תוכני המסך והניקוד מוצגים כנדרש.
- מעבר לאודות בזמן הצגת רצף עוצר את ההצגה; בחזרה היא נמשכת באופן עקבי ללא דילוג, כפילות או קלט בלתי צפוי.
- מעבר לאודות במהלך שחזור רצף משמר את מיקום הקלט, הרצף והניקוד.
- חזרה מאודות אינה מתחילה משחק חדש ואינה משנה את שיא הסשן.
- קיימים שני מסכים בלבד; סיום משחק נשאר מצב של מסך המשחק.
- בדיקות UI לניווט ולהשהיה עוברות, והפריסה נבדקת בגודל מסך נייד.

## Milestone 4 – PWA, Offline ופרסום אוטומטי

**שם ומטרה:** להפוך את המשחק לאתר נייד הניתן להתקנה ולשימוש Offline, ולפרסם אותו דרך GitHub Pages.

**מה יש לממש:**
- הגדרת `vite-plugin-pwa` עם Manifest, אייקונים נדרשים ו־Service Worker ב־`generateSW`, תוך שמירת קובצי האפליקציה הדרושים ב־Precache.
- בדיקת פעולה לאחר טעינה ראשונית ללא אינטרנט, ללא אחסון מצב משחק מתמשך.
- התאמת נתיבי ה־Build וה־Assets לנתיב הפרויקט ב־GitHub Pages.
- GitHub Actions לבדיקות, Typecheck, Build ו־Deployment אוטומטי מ־`main` ל־GitHub Pages.
- אימות הממשק, הצלילים והניווט בדפדפן נייד; טיפול בהתנהגות דפדפן בעת מעבר לרקע ובחזרה, בהתאם ל־`ARCHITECTURE.md`.
- בדיקות מסכמות של משחק מלא, ניווט, איפוס ברענון והתקנה.

**תוצר מצופה:** כתובת HTTPS פעילה ב־GitHub Pages, שבה המשחק המלא זמין בנייד, ניתן להתקנה כ־PWA ופועל Offline לאחר טעינה ראשונית.

**Definition of Done:**
- Push ל־`main` מפעיל Workflow שמריץ בדיקות ו־Build ומפרסם בהצלחה ל־GitHub Pages.
- האתר נטען בכתובת ה־Production, ומשאבי CSS/JavaScript/Manifest נטענים כראוי גם בנתיב Repository.
- ה־PWA מציע את יכולת ההתקנה הנתמכת במכשיר/דפדפן; התקנה למסך הבית נבדקת במכשיר תומך.
- לאחר טעינה ראשונית מלאה, ניתן לטעון מחדש ולשחק כשהרשת מנותקת, כל עוד משאבי ה־Cache נשמרו.
- רענון הדף מאפס משחק וניקוד גם במצב Offline; Cache משמש לקובצי האפליקציה בלבד.
- משחק מלא, הפסד, ניצחון, התחלה מחדש, מעבר לאודות והשהיה עובדים בגרסה הפרוסה.
- בדיקות אוטומטיות עוברות; נבדקת התאמה למובייל ול־RTL.
- המשתמש מקבל את כתובת האתר ואת תוצאות הבדיקות לאישור.

## Development Execution Rules – כללי ביצוע מחייבים ל־AI

1. יש לפתח את ה־Milestones **לפי הסדר** המוגדר במסמך; אין לדלג על אבן דרך או להתחיל את הבאה מוקדם.
2. לאחר השלמת כל Milestone, יש **לעצור את הפיתוח** ולהציג למשתמש את התוצר העובד, את אופן הבדיקה ואת תוצאות הבדיקות מול כל סעיפי ה־Definition of Done.
3. **אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש.**
4. אם תנאי השלמה אינו מתקיים, יש לתקן ולבדוק מחדש במסגרת אותו Milestone, ולא להציג אותו כהושלם.
5. יש לשמור על התאמה למסמכי `PRD.md`, `ARCHITECTURE.md` ו־`DESIGN.md`; אין להוסיף פיצ'רים או מסכים שלא הוגדרו בהם.

> אין בפרויקט Backend או Database, ולכן אין צורך בסביבות Supabase או ב־Database Migrations.
