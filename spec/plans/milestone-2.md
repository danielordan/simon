# תוכנית – Milestone 2: מחזור משחק מלא, ניקוד וסיום

> מבוסס על `MILESTONES.md` (Milestone 2), `PRD.md`, `ARCHITECTURE.md`, `DESIGN.md`, התמונות `wireframes.png` ו-`mockups.png`, והקוד הקיים אחרי Milestone 1.
> תאריך: 21.10.2026

## 0. מטרה בקצרה

להפוך את המשחק הראשוני למשחק Simon שלם: בכל שלב נוסף צבע אחד לרצף (עד 10), השלמת שלב מוסיפה נקודה ומתקדמת אוטומטית, טעות ראשונה מסיימת את המשחק עם צליל שגיאה והבהוב אדום, השלמת שלב 10 היא ניצחון. בסיום מוצג כרטיס תוצאה (הפסד אדום / ניצחון ירוק) עם ״משחק חדש״. שיא הסשן נשמר בזיכרון הדף.

**לא בתחום Milestone 2** (נבנה בהמשך): מסך אודות, ניווט אליו, השהיה, מעבר לרקע ו״הקש להמשך״ (M3); PWA ופריסה (M4).
- אייקון ״אודות״ בפס העליון וכפתור ״אודות״ המשני בכרטיס הסיום **יוצגו אך לא יפעלו** עד M3 (כמו האייקון ב-M1).
- שיא הסשן מוצג רק במסך אודות (M3). ב-M2 הוא נשמר ב-State ונבדק בבדיקות אוטומטיות, אבל עדיין לא נראה בממשק.

## 1. שינויים בלוגיקת המשחק

### 1.1 `game/reducer.ts` (Game Controller)

פעולות (Actions):

| פעולה | מצב נדרש | תוצאה |
|---|---|---|
| `START { color }` | `idle` / `won` / `lost` | `sequence=[color]`, `inputIndex=0`, `score=0`, `phase='showing'`; `sessionBest` נשמר. משמש גם ל״התחל״ וגם ל״משחק חדש״ |
| `SHOW_DONE` | `showing` | ללא שינוי (`phase='input'`, `inputIndex=0`) |
| `PRESS { color }` – נכון, לא אחרון | `input` | `inputIndex+1` (ללא שינוי ניקוד) |
| `PRESS` – נכון ואחרון | `input` | `score+1`, `sessionBest=max(...)`; אם `sequence.length === TOTAL_STAGES` → `phase='won'`, אחרת `phase='success'` |
| `PRESS` – שגוי | `input` | `phase='lost'`; `score` ו-`sequence` נשמרים (נדרשים לכרטיס התוצאה) |
| `SUCCESS_DONE { color }` | `success` | `sequence=[...sequence, color]` (בדיוק צבע אחד), `inputIndex=0`, `phase='showing'` |

- הצבע החדש מוגרל ב-hook (עם ה-`rng` המוזרק) ומועבר בפעולה, כך שה-reducer נשאר טהור.
- פעולה במצב לא מתאים מחזירה את אותו אובייקט State (כמו היום) — מונע מעברים כפולים מלחיצות מהירות.
- הערות ה-"Milestone 1" בקוד יוסרו.

### 1.2 `game/rules.ts`

- `currentStage` נשאר `max(1, sequence.length)`.
- פונקציה חדשה `reachedStage(state)` לכרטיס הסיום: בניצחון `TOTAL_STAGES`, בהפסד `score + 1`.
- `appendColor` כבר קיימת — ה-hook ישתמש ב-`randomColor` כדי להעביר צבע לפעולה (כמו ב-START).

### 1.3 `audio/audio.ts`

- פונקציה חדשה `playError(ms)`: צליל שגיאה מובחן ונמוך (Oscillator מסוג `sawtooth` בכ-`110Hz`), עם אותו Gain Envelope נגד Clicks, ועוצר צליל קודם (`stopAll`).
- הקבוע `ERROR_TONE` יתווסף ל-`game/constants.ts` לצד `TONES`.

### 1.4 `hooks/useGame.ts` (תזמונים וביטול)

- **success → השלב הבא:** אחרי `TIMINGS.successPause` (1000ms) — `dispatch({ type: 'SUCCESS_DONE', color: randomColor(rng) })`. ה-effect הקיים של `showing` יפעיל אוטומטית את הצגת הרצף החדש (כולל `leadIn` של 700ms).
- **״חשיפת״ כרטיס הסיום (UI בלבד):** State מקומי `resultVisible` (או `endRevealPending`):
  - בהפסד: הלחיצה השגויה מבטלת את הארת הלחיצה הקודמת, מפעילה `playError(TIMINGS.errorFlash)` ומסמנת `errorFlash=true`; אחרי 600ms — `errorFlash=false` והכרטיס מוצג.
  - בניצחון: הלחיצה האחרונה מוארת ונשמעת כרגיל (300ms); בסיום ההארה הכרטיס מוצג — ללא ״כל הכבוד!״ וללא השהיית ההצלחה.
  - ההחלטה אם להציג כרטיס מבוססת על `phase` (`won`/`lost`) + שהטיימר של ההבהוב/ההארה הסתיים. כך ב-M3 אפשר יהיה לבטל את הטיימר בעת יציאה ולהציג את הכרטיס ישירות (`ARCHITECTURE.md` 2.5).
- **פעולה חדשה `newGame()`:** מותרת רק ב-`won`/`lost` אחרי שהכרטיס מוצג; קוראת `ensureAudio()` (מחוות משתמש), מאפסת את State ה-UI (`litColor`, הבהוב) ושולחת `START` עם צבע חדש. `start()` ו-`newGame()` יכולים לחלוק את אותה פונקציה פנימית.
- **ביטול פעולות ממתינות:** כל Timer (הארת לחיצה, הבהוב שגיאה, השהיית הצלחה, הצגת רצף) נשמר ב-Ref או ב-cleanup של effect ומבוטל במעבר מצב, בהתחלת משחק חדש ובפירוק הרכיב. ה-Generation guard הקיים (`active`) נשמר. `phaseRef` ממשיך לחסום קלט שאינו ב-`input`.

## 2. ממשק המשתמש

### 2.1 `App.tsx`

- כש-`phase` הוא `won`/`lost` **והכרטיס נחשף**: מתחת ל-`TopBar` מוצג רק `ResultCard` (במקום תיבות הנתונים, הלוח ואזור ההודעה), לפי ה-Wireframe וה-Mockup.
- אחרת — המסך הרגיל (תיבות, לוח, אזור הודעה). בזמן הבהוב השגיאה הלוח עדיין מוצג (עם ההבהוב).

### 2.2 `SimonBoard`

- Prop חדש `errorFlash: boolean` → `data-error="true"` על הלוח.
- CSS: בזמן ההבהוב כל ארבעת הרבעים מקבלים גוון/שכבה אדומה (`Red #EF4444`) וזוהר אדום סביב הלוח; עם `prefers-reduced-motion` — בלי זוהר/אנימציה, רק שינוי הצבע.

### 2.3 `StatusArea`

- ההודעות ״צפה ברצף״ / ״תורך!״ / ״כל הכבוד!״ נשארות.
- ב-`lost` בזמן ההבהוב — אזור ההודעה נשאר ריק (או מציג את ההודעה האחרונה ללא שינוי); אין כפתור.

### 2.4 רכיב חדש `components/ResultCard.tsx`

לפי `DESIGN.md` 1.2 וה-Mockup:

| | הפסד | ניצחון |
|---|---|---|
| רקע ומסגרת | `Error Card Tint #2A2128`, מסגרת וזוהר `Red` | `Dark Card`, מסגרת וזוהר `Green` |
| אייקון עליון | X בעיגול אדום | גביע (`Accent Gold` / ירוק) |
| כותרת (H1) | ״אוי לא!״ | ״כל הכבוד! ניצחת!״ |
| טקסט משני | ״המשחק הסתיים.״ | — |
| תיבה 1 | ״השלב שהושג״ – `score+1 / 10` (אייקון עמודות) | ״השלב שהושג״ – `10 / 10` |
| תיבה 2 | ״הניקוד הסופי״ – `score` (אייקון גביע) | ״הניקוד הסופי״ – `10` |
| כפתור ראשי | ״משחק חדש״ אדום (`Danger Button`) + אייקון Restart | ״משחק חדש״ כחול (`Primary Button`) + אייקון Restart |

- הכרטיס עטוף ב-`aria-live="polite"` כדי שהתוצאה תוכרז.
- ערכי `x / 10` עם `dir="ltr"` (כמו ב-`StatBoxes`).
- אייקונים חדשים ב-`icons.tsx`: `CloseCircleIcon` (X) ו-`RestartIcon`, באותו משקל קו.
- הכרטיס חייב להיכנס במסך `360×640` בלי גלילה.

### 2.5 `styles.css`

- סגנונות `.result-card` (שני הגוונים), תיבות הנתונים האנכיות בכרטיס, `.button--danger`, `.button--secondary`, והבהוב השגיאה של הלוח.
- שימוש ב-Tokens הקיימים ב-`:root`; הוספת Tokens חסרים (`--error-card`, `--secondary-button`, `--danger`) אם אינם קיימים.

## 3. בדיקות אוטומטיות (Vitest + RTL)

RNG ידוע מראש בבדיקות (למשל רצף קבוע של מחזור צבעים), ו-Fake Timers.

**`reducer.test.ts` / `rules.test.ts`:**
- `SUCCESS_DONE` מוסיף בדיוק צבע אחד, והרצף הקודם נשמר באותו סדר.
- אורך הרצף שווה למספר השלב בכל שלב 1–10.
- לחיצה נכונה חלקית לא משנה ניקוד; השלמת שלב מוסיפה נקודה אחת.
- השלמת שלב 10 → `won`, ניקוד 10, אין שלב 11 (`SUCCESS_DONE` ב-`won` לא עושה דבר).
- לחיצה שגויה בכל שלב → `lost`; לחיצות נוספות אחרי זה מתעלמות.
- `reachedStage`: הפסד = `score+1`, ניצחון = 10.
- `START` מ-`won`/`lost` מאפס ניקוד ורצף ומשמר `sessionBest`; שיא נשמר רק אם הניקוד גבוה יותר.

**`App.test.tsx` (זרימות UI):**
- מעבר אוטומטי לשלב 2 אחרי ״כל הכבוד!״ + 1000ms, הצגת רצף של 2 צבעים ו״2 / 10״.
- הפסד: צליל שגיאה, `data-error` על הלוח למשך 600ms, ורק אחריו כרטיס ״אוי לא!״ עם השלב שהושג והניקוד הסופי הנכונים.
- ניצחון: משחק מלא של 10 שלבים → כרטיס ״כל הכבוד! ניצחת!״ עם `10 / 10` ו-10, בלי ״כל הכבוד!״ ביניים.
- ״משחק חדש״ → רצף חדש, ניקוד 0, ״1 / 10״.
- אחרי סיום — אין Timers שממשיכים להאיר/להשמיע (מתקדמים בזמן ובודקים שאין שינוי).
- לחיצות בזמן ״צפה ברצף״ עדיין מתעלמות גם בשלבים מתקדמים.

עדכון בדיקת M1 הקיימת (״חוזר ל-התחל אחרי ההצלחה״) — כעת ההתנהגות היא מעבר לשלב 2.

1. `npm run typecheck`, `npm test`, `npm run build` — ללא שגיאות.

## 6. מיפוי ל-Definition of Done

| תנאי | איך מתקיים |
|---|---|
| אורך הרצף = מספר השלב, הרצף הקודם נשמר | `SUCCESS_DONE` מוסיף צבע אחד לסוף; בדיקות reducer |
| קלט חלקי לא מוסיף נקודה; שלב מלא +1 ומעבר אוטומטי | reducer + Timer של 1000ms; בדיקות reducer ו-UI |
| שלב 10 → ניצחון ישיר, `10 / 10`, 10 נקודות, אין שלב 11 | `PRESS` אחרון בשלב 10 → `won`; `ResultCard`; בדיקת UI מלאה |
| בהפסד ״השלב שהושג״ = ניקוד + 1 | `reachedStage`; בדיקות |
| טעות מסיימת מיד עם משוב חזותי וקולי | `playError` + `data-error`; כרטיס אחרי 600ms |
| ״משחק חדש״ → רצף חדש וניקוד 0 | `START` מ-`won`/`lost`; בדיקת UI |
| שיא הסשן נשמר בין משחקים ומתאפס ברענון | `sessionBest` ב-State בזיכרון בלבד; בדיקות reducer (התצוגה עצמה ב-M3) |
| בדיקות מכסות התקדמות, ניקוד, שגיאה, ניצחון ואיפוס | סעיף 3 |
