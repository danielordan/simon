## 0. מטרה בקצרה

להוסיף את המסך השני — ״אודות״ — ואת המעבר אליו וממנו, בלי לאבד משחק פעיל: מעבר לאודות משהה את המשחק, והחזרה ממשיכה לפי המצב שבו עזבו. בנוסף, טיפול במעבר האפליקציה לרקע (מעבר לאפליקציה אחרת / נעילת מסך) באמצע הצגת רצף או בהשהיה שאחרי ״כל הכבוד!״ — בחזרה מוצג כפתור ״הקש להמשך״.

**לא בתחום Milestone 3:** PWA, Offline, אייקוני אפליקציה ופריסה (M4). אין Router, אין URL חדש ואין מסך שלישי.

## 1. לוגיקת המשחק

### 1.1 `game/types.ts`

הרחבת `GameState` לפי `ARCHITECTURE.md` 2.3:

```ts
type Screen = 'home' | 'about';
type GameState = {
  ...הקיים,
  screen: Screen;          // המסך המוצג
  awaitingResume: boolean; // מוצג ״הקש להמשך״; ההצגה עצורה עד הלחיצה
};
```

ב-`initialState`: `screen: 'home'`, `awaitingResume: false`. רענון הדף מאפס הכול (אין שמירה מתמשכת — ללא שינוי).

### 1.2 `game/reducer.ts` – פעולות חדשות

| פעולה | מצב נדרש | תוצאה |
|---|---|---|
| `OPEN_ABOUT` | `screen='home'` (כל `phase`) | `screen='about'`; `phase`, `sequence`, `inputIndex`, `score` נשמרים כמו שהם |
| `CLOSE_ABOUT { color }` | `screen='about'` | `screen='home'`, `awaitingResume=false`; אם `phase='success'` → מוסיף את `color` לסוף הרצף, `inputIndex=0`, `phase='showing'` (בדיוק כמו `SUCCESS_DONE`); בכל מצב אחר — ללא שינוי |
| `GO_BACKGROUND` | `screen='home'` ו-`phase` הוא `showing` או `success` | `awaitingResume=true`; בכל מצב אחר (כולל `screen='about'`, `input`) — אותו State, ללא שינוי |
| `RESUME { color }` | `awaitingResume=true` | `awaitingResume=false`; אם `phase='success'` → מוסיף צבע ועובר ל-`showing` (כמו למעלה); אם `showing` — ללא שינוי נוסף (ההצגה תתחיל מחדש מהצבע הראשון) |

- `START` (״התחל״/״משחק חדש״) מאפס גם `awaitingResume=false`; `screen` נשאר `home`.
- **צבע נוסף רק במעבר success → showing** (`SUCCESS_DONE`, `CLOSE_ABOUT`, `RESUME`). שלושתם ישתמשו בפונקציית עזר אחת פנימית ב-reducer (`advanceStage`) כדי שלא יהיו שלוש גרסאות של אותו כלל.
- `PRESS` מתקבל רק כש-`phase='input'` **וגם** `screen='home'` (`ARCHITECTURE.md` 2.4, כללי עקביות).
- `OPEN_ABOUT` / `CLOSE_ABOUT` / `RESUME` **לא נוגעים** ב-`score` או ב-`sessionBest` — כך ״חזרה מאודות אינה משנה את שיא הסשן״.
- הצבע החדש מוגרל ב-hook (עם ה-`rng` המוזרק) ומועבר בפעולה, כמו היום — ה-reducer נשאר טהור. אם הפעולה לא צריכה צבע (למשל `showing`), הוא פשוט לא בשימוש.

### 1.3 `hooks/useGame.ts` – השהיה וחידוש

**עיקרון מרכזי:** ההצגה (Scheduler) וטיימר ההצלחה רצים **רק** כשמותר להם:

```text
canRun = state.screen === 'home' && !state.awaitingResume
```

- ה-effect הקיים של `showing` ושל `success` יקבל את `canRun` כתנאי וכתלות (dependency). כשעוברים לאודות או לרקע, `canRun` נהיה `false` → ה-cleanup הקיים מבטל את כל ה-Timers, מכבה את ההארה ועוצר צליל (`stopAll`). כשחוזרים, ה-effect רץ מחדש → **הרצף מוצג מהצבע הראשון** (כולל המתנת `leadIn` של 700ms). אין צורך לשמור ״זמן שנותר״.
- ה-Generation guard הקיים (`active`) נשמר — Callback מאוחר מהצגה שבוטלה לא עושה דבר.

**פעולות חדשות שה-hook מחזיר:**

- `openAbout()`:
  1. `finishPendingVisuals()` (ראה בהמשך).
  2. `send({ type: 'OPEN_ABOUT' })`.
- `closeAbout()`:
  1. `ensureAudio()` — הלחיצה היא מחוות משתמש, ולכן מחדשים בה את ה-AudioContext.
  2. `send({ type: 'CLOSE_ABOUT', color: randomColor(rng) })`.
- `resume()` (״הקש להמשך״):
  1. `ensureAudio()`.
  2. `send({ type: 'RESUME', color: randomColor(rng) })`.

**`finishPendingVisuals()`** – פונקציית עזר פנימית שמסיימת מיד כל משוב חזותי/קולי שעדיין ״באוויר״:
- מבטלת `pressTimer` ו-`endTimer`, מכבה `litColor` ו-`errorFlash`, ועוצרת צליל (`stopAll`).
- אם `phase` הוא `lost` או `won` → `resultVisible=true`. כך מעבר לאודות/לרקע **באמצע הבהוב השגיאה** (או באמצע הארת הלחיצה האחרונה בניצחון) מציג בחזרה ישירות את כרטיס הסיום, **בלי** להשמיע שוב את צליל השגיאה (`ARCHITECTURE.md` 2.5).
- ב-`input`: רק מכבה את הארת הלחיצה האחרונה; `inputIndex` נשמר → השחקן ממשיך מאותה לחיצה.

**מעבר לרקע (Page Visibility API):** effect חדש שמאזין ל-`visibilitychange` על `document`:
- כש-`document.visibilityState === 'hidden'`:
  - אם `screen='about'` — לא עושים כלום (`ARCHITECTURE.md` 2.5: הטיפול פועל רק במסך המשחק).
  - אחרת: `finishPendingVisuals()` + `send({ type: 'GO_BACKGROUND' })`. ה-reducer מחליט: רק ב-`showing`/`success` נדלק `awaitingResume`; ב-`input` אין שינוי (ממשיכים כרגיל, וה-AudioContext מתחדש בלחיצה הבאה — כבר קורה היום ב-`press`).
- כשהדף חוזר לחזית — אין צורך בפעולה: `awaitingResume` כבר `true`, ולכן המשתמש רואה ״הקש להמשך״ וההצגה עצורה.
- ה-listener מוסר בפירוק הרכיב.

> **החלטה טכנית (תתועד כ-ADR):** `awaitingResume` נדלק **ברגע היציאה לרקע** (ולא ברגע החזרה, כפי שכתוב בטבלה ב-2.4). התוצאה למשתמש זהה — בחזרה מוצג ״הקש להמשך״ — אבל כך ה-Timers נעצרים מיד ע״י אותו מנגנון `canRun`, בלי טיימרים שממשיכים לרוץ (באיטיות) ברקע ובלי צורך בשני אירועים נפרדים.

**הגנות נוספות:**
- `press()` בודק `phase === 'input' && screen === 'home'` (דרך `stateRef`).
- `start()` לא משתנה (״התחל״/״משחק חדש״ זמינים רק במסך המשחק ממילא).
- מקרה קצה: אם `awaitingResume=true` והשחקן פותח אודות וחוזר — `CLOSE_ABOUT` מאפס את `awaitingResume` וממשיך כרגיל (הלחיצה על ״חזרה למשחק״ היא מחוות משתמש שמאפשרת צליל), כלומר ההתנהגות זהה ל״הקש להמשך״.

## 2. ממשק המשתמש

- `state.screen === 'about'` → מציג `<AboutScreen>` **במקום** כל תוכן מסך המשחק (כולל הפס העליון שלו). אחרת — מסך המשחק כפי שהוא היום (כולל כרטיס הסיום כמצב של מסך המשחק).

## 3. בדיקות אוטומטיות (Vitest + RTL, Fake Timers, RNG קבוע)

**`reducer.test.ts`:**
- `OPEN_ABOUT` / `CLOSE_ABOUT` ב-`showing` ו-`input`: הרצף, `inputIndex`, הניקוד והשיא נשמרים; אין צבע חדש.
- `CLOSE_ABOUT` ב-`success`: נוסף בדיוק צבע אחד, `phase='showing'`, `inputIndex=0`.
- `CLOSE_ABOUT` ב-`idle`/`won`/`lost`: רק `screen` משתנה.
- `GO_BACKGROUND`: ב-`showing`/`success` במסך המשחק → `awaitingResume=true`; ב-`input`, ב-`idle` וכש-`screen='about'` → אותו State.
- `RESUME`: ב-`showing` → ללא צבע חדש; ב-`success` → בדיוק צבע אחד.
- `PRESS` כש-`screen='about'` → מתעלמים.
- `sessionBest` לא משתנה באף אחת מפעולות הניווט.

**`App.test.tsx` (זרימות UI):**
- פתיחת אודות מהאייקון (i) ומכפתור ״אודות״ בכרטיס הסיום; כל התכנים מוצגים (שם, תיאור, 4 הוראות, ניקוד נוכחי, שיא); חזרה בכפתור ״חזרה למשחק״ ובחץ.
- אודות לפני משחק → חזרה ל״התחל״; אחרי סיום → חזרה לכרטיס הסיום, הניקוד הנוכחי = הניקוד הסופי.
- **אודות בזמן הצגה:** באמצע הרצף (שלב 2+) → לא נשמעים צלילים נוספים ולא נדלקת הארה גם אחרי שעובר זמן; בחזרה — אותו רצף מהצבע הראשון (רשימת הצלילים שהושמעו תואמת בדיוק לרצף), אותו אורך, ״צפה ברצף״, לחיצות חסומות עד ״תורך!״.
- **אודות בתור השחקן:** אחרי לחיצה נכונה אחת מתוך שתיים → חזרה → הלחיצה הבאה ממשיכה מהמקום ומשלימה את השלב; הרצף לא מוצג שוב.
- **אודות בהשהיה שאחרי ״כל הכבוד!״:** חזרה → השלב הבא (`n+1 / 10`), נוסף בדיוק צבע אחד, הרצף החדש מוצג מתחילתו; הטיימר הישן של ההשהיה לא מוסיף צבע נוסף.
- **אודות באמצע הבהוב השגיאה:** חזרה → כרטיס ״אוי לא!״ מוצג מיד, בלי צליל שגיאה נוסף.
- **רקע באמצע הצגה:** (הדמיית `document.visibilityState` + אירוע `visibilitychange`) → אין צלילים/הארה בזמן ההיעדרות; בחזרה מוצג ״הקש להמשך״ והלוח חסום; אחרי הלחיצה הרצף מוצג מתחילתו עם צליל.
- **רקע בהשהיה שאחרי ״כל הכבוד!״:** ״הקש להמשך״ → נוסף צבע אחד והרצף החדש מוצג.
- **רקע בתור השחקן:** אין ״הקש להמשך״, הקלט ממשיך.
- **רקע באמצע הבהוב השגיאה:** בחזרה מוצג כרטיס ההפסד.
- **רקע כשמסך אודות פתוח:** בחזרה מסך אודות עדיין מוצג, בלי ״הקש להמשך״; ״חזרה למשחק״ ממשיכה כרגיל.
- חזרה מאודות לא מתחילה משחק חדש ולא משנה את שיא הסשן.
- קיימים שני מסכים בלבד: בכל רגע מוצג או מסך המשחק או מסך אודות; כרטיס הסיום מוצג בתוך מסך המשחק.

עדכון בדיקות קיימות במידת הצורך (למשל שתי תוויות ״אודות״ — האייקון והכפתור בכרטיס הסיום — ושתי תוויות ״חזרה למשחק״ במסך אודות; שימוש ב-`getAllByRole` היכן שצריך).
